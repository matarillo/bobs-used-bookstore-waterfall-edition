# データモデル設計

Bob's Used Bookstoreの販売・買取を、業務事実を正本とする単一PostgreSQLのモデルとして定義する。
対象は両フェーズのデータ構造・書込み契約・照会・整合性の検証である。基本設計案であり、要件の合意状態を変更しない。

## 入力と出典

業務語彙は[用語定義](../../glossary.md)、要求の正本は[要件定義書](../../requirements/README.md)である。
画面イメージは入出力の補足として読み、合意済みルール・決定事項を優先する。
方法論は[業務データモデリングのパターンランゲージ・詳細版](https://github.com/matarillo/data-modeling-pattern-language/blob/main/docs/report-detailed.md)のP001〜P012を用いる。
設計原則とP001〜P012の適用箇所は[概念モデル](conceptual-model.md#パターンの適用)に定める。

要件・用語・画面資料33ファイルの内容は[ベースライン](validation/requirements-baseline.json)と照合する。
`agreed` の要求をこの設計から上書きしない。要件と異なる要求を追加する際は要件側の変更管理を経る。

## 設計仮定

以下は要件で明記されていない部分についての設計案である。

| ID | 採用する定義 |
| --- | --- |
| A01 | 単一通貨、小数2桁、保存は `numeric(19,2)`。入力は小数2桁以内とし、浮動小数点で金額を計算しない。四捨五入は非負値に対するHALF_UP。通貨コードの具体値はこのモデルに埋め込まない |
| A02 | 税抜単価×整数数量を合計して注文小計を作り、小計×0.10を一度だけ小数2桁へ丸める。合計＝小計＋税。顧客向け一覧の単品価格も税込表示へ整形する。粗利は負値を認める |
| A03 | 全時点はUTC。納品予定日はUTCの注文日付＋7日で、UTCの現在日付が予定日を超えたら納期超過とする |
| A04 | ログイン時、既存の顧客かごへ未ログインかごを統合する。同じ書籍・種別の数量は最大値とし、種別をまたいで混ぜない。在庫超過は自動減数せず、注文前に再確認させる |
| A05 | 参照データ名は前後の空白を除去し、同じ種別内で大文字小文字を区別せず一意とする。種別が違う同名は許容する |
| A06 | 顧客は外部認証基盤の `sub` で識別し、メールはローカルに複製しない。パスワード・トークン・管理者グループを業務DBに保存しない |
| A07 | 注文・買取申込・原価・数量の汎用的な事後訂正機能は設けない。書籍の現在属性を訂正する操作と、成立した注文を取り消す操作を区別する |
| A08 | 冪等記録は取引記録と同じく無期限保持とし、同じキーの再利用を認めない。DB内の結果だけを保証対象とする |
| A09 | 書籍IDは在庫管理単位を識別する。数量を持ち、ISBNの一致は同じ在庫単位を意味しない。異なる仕入原価の在庫は別書籍IDにする |
| A10 | 書名・著者・分類4軸・住所行1・市・州・郵便番号を必須とし、ISBN・住所行2・表紙画像は任意とする。郵便番号は5桁またはZIP+4、州は50州＋DC、国はUSとする |

`ENT-CUSTOMER` の主要項目と業務フローにはメールの取込みを示す記載がある一方、07章§5・08章・11章は外部認証基盤での保持を定める。A06は後者に合わせた設計仮定である。
買取価格の凍結時点は07章§3の申込時を採る。価格変更を提供する機能要件はなく、支払後だけの変更禁止を価格変更機能の追加根拠にしない。

## 適用範囲と規模

物理表は17表。要件の主要エンティティ10種を、成立事実・在庫の増減・現在状態・冪等記録へ分ける。
要件10章の12表という規模見当とは差がある。追加機能を意味するものではなく、設計・試験工数への影響は見積レビューの対象となる。
データ量は要件07章の3年後の見当を入力とし、履歴表の件数は操作回数に応じて増える。
マイクロサービス、非同期CQRS、全属性の履歴、二時制、販売側の入金、送金、返金、部分取消、返品は導入しない。

DDLは[作成用SQL](sql/schema.sql)と[ビュー](sql/views.sql)。空のDBへ順に適用する。表・列・制約の正本はDDLであり、データ辞書と論理ER図は実DBカタログから生成する。
実行可能な更新例は[検証用契約](validation/contracts.mjs)にある。これを本番APIやDAOとして採用しない。

## 実行

対象リポジトリのルートからPowerShell 7で実行する。Node・PostgreSQL 18のバイナリをPATHへ設定する。

```powershell
./docs/design/data-model/validation/Manage-Postgres.ps1 -Action Start
node docs/design/data-model/validation/run.mjs
node docs/design/data-model/validation/build-docs.mjs --check
node docs/design/data-model/validation/check-docs.mjs
./docs/design/data-model/validation/Manage-Postgres.ps1 -Action Stop
```

専用クラスタはリポジトリの `.local/data-model-postgres/data`、待受は127.0.0.1:55468、DB名は `bobs_model_validation`。
検証ランナーはクラスタの実パスとDB名を検査してから、専用DB内の `bookstore` スキーマを作り直す。
ローカル使い捨て環境に限りtrust認証を使う。本番の資格情報・接続先は収録しない。
