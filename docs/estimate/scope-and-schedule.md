## 2. 工数

技術方式は [ADR-0004](../requirements/decisions/ADR-0004-technology-stack.md) を前提とする。

| 工程 | 内容 | 人月 |
| --- | --- | --- |
| 基本設計 | 画面設計書 26 版面、API 定義 45、テーブル定義 12、外部 I/F 設計 5 | 4.5 |
| 詳細設計・実装・単体テスト | 画面・API・永続化の実装と自動テスト | 12.0 |
| 結合テスト | 画面と API を通した業務シナリオ | 3.0 |
| 総合テスト | 非機能要件の [必達] 項目の検証を含む | 2.0 |
| 移行・リリース | 環境構築、参照データ投入、操作説明会 | 1.0 |
| プロジェクト管理 | 全工程を通じた進捗・課題・品質の管理 | 2.5 |
| **合計** | | **25.0** |

**金額は 人月単価 × 25.0 人月 とする。** 単価は契約条件として別途定める。

### 2.1 工数の根拠

| 単位 | 単価（人日） | 数 | 小計（人日） |
| --- | --- | --- | --- |
| 画面（基本設計〜単体テスト） | 5.0 | 26 版面 | 130 |
| API（基本設計〜単体テスト） | 2.5 | 45 | 113 |
| テーブル（設計・DDL・初期データ） | 1.5 | 12 | 18 |
| 外部インタフェース | 6.0 | 5 | 30 |
| 共通基盤（認証・エラー処理・画面共通部品・ビルドと配置の自動化） | — | 一式 | 40 |
| **小計（基本設計〜単体テスト）** | | | **331 ≒ 16.5 人月** |

結合・総合・移行・管理を加えて 25.0 人月。**1 人月 ＝ 20 人日**で換算する。

### 2.2 見積に含まないもの

- 稼働後の保守・運用代行（別契約）
- 初期在庫 500 冊の登録作業（店が行う — [11 §4](../requirements/11-constraints-and-assumptions.md)）
- ドメイン名・証明書の取得（店が行う）
- AWS の利用料（店が直接負担する）
- [12 §4](../requirements/12-open-issues-and-risks.md) に挙げた「扱わないと確定した事項」

## 4. スケジュール

要件定義完了の翌月を第 1 月とする。

| 月 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 基本設計 | ●● | ● | | | | | |
| 詳細設計・実装・単体（フェーズ 1） | | ●● | ●● | ●● | | | |
| 詳細設計・実装・単体（フェーズ 2） | | | | ● | ●● | | |
| 結合テスト | | | | ● | ●● | ● | |
| 総合テスト | | | | | | ●● | ● |
| 移行・リリース | | | | | | | ●● |

| 里程標 | 時期 |
| --- | --- |
| 基本設計完了レビュー | 第 3 月末 |
| フェーズ 1 結合テスト完了 | 第 5 月末 |
| 総合テスト完了 | 第 7 月中旬 |
| **フェーズ 1・2 同時リリース／検収** | **第 7 月末** |

**フェーズ 1 と 2 を同時にリリースする。**
フェーズ分割は [02 §4](../requirements/02-scope.md) のとおり**作る順序**であり、
リリースを分けると環境と検収が二重になって費用が増える。

**納期が逼迫した場合は、フェーズ 2 を切り離して後続の便に載せる。**
そのときフェーズ 1 のみで検収する。判断の期限は第 4 月末とする。

## 5. 再見積の引き金

次のいずれかが起きたとき、**作業を止めて再見積を行う。**

| 引き金 | 出典 |
| --- | --- |
| [11 §5](../requirements/11-constraints-and-assumptions.md) の前提が崩れたとき | 前提と制約 |
| 機能が 3 件を超えて追加されたとき、または画面が 2 版面を超えて追加されたとき | 本書 §1 |
| 技術方式を変更するとき | [ADR-0004](../requirements/decisions/ADR-0004-technology-stack.md) |
| [12 §4](../requirements/12-open-issues-and-risks.md) の「扱わないと確定した事項」を実施すると決めたとき | 課題とリスク |
| 顧客の回答が 3 営業日を超えて滞り、累積 10 営業日に達したとき | [11 §4](../requirements/11-constraints-and-assumptions.md) |

**上記に至らない軽微な変更は、工程内で吸収する。**
吸収した変更は変更管理台帳に記録し、各工程の完了レビューで累積を確認する。
