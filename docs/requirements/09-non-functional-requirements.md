# 09 非機能要件

「どれだけの品質で作るか」を定める。**測り方まで含めて合意する。**
測れないものは要件ではなく、[11 前提と制約](11-constraints-and-assumptions.md) に前提として置く。

## 1. 品質水準の考え方

**この店の判断は明快である。守るのは「取引と個人情報の正しさ・安全」だけであり、
性能・可用性・アクセシビリティには高い水準を求めない。**

小規模な単一店舗の EC であり、月額運用費の上限が品質の上限を規定する
（[11 §3](11-constraints-and-assumptions.md)）。

| 強制 | 意味 |
| --- | --- |
| **[必達]** | 満たさなければ検収しない |
| **[目標]** | 努力目標。未達でも検収を妨げない |
| **[対象外]** | 水準を定めない。定めないことを合意する |

## 2. 可用性

| ID | 要件 | 測定 | 強制 |
| --- | --- | --- | --- |
| `NFR-AVAIL-01` | サービス時間は 24 時間 365 日とする。計画停止は事前告知のうえ月 1 回・2 時間以内 | 告知外の停止が月 1 回を超えないこと | [目標] |
| `NFR-AVAIL-02` | 稼働率の水準を定めない。**実行単位は 1 つであり、停止すれば店は閉まる**。異常終了時の自動再起動のみ備える | — | [対象外] |
| `NFR-AVAIL-03` | データベースのバックアップは 1 日 1 回・7 日保持とする。目標復旧時点 (RPO) 24 時間、目標復旧時間 (RTO) 8 時間 | 復旧手順の実地確認を総合テストで 1 回行うこと | [必達] |

**`NFR-AVAIL-03` は運用費の増加を伴う。** 買取の支払記録が失われると顧客との金銭トラブルに
直結するため、コスト上限に優先させる（[D-13](decisions/README.md)）。

## 3. 性能・拡張性

| ID | 要件 | 測定 | 強制 |
| --- | --- | --- | --- |
| `NFR-PERF-01` | 通常操作の画面表示は 3 秒以内 | 想定データ量（[07 §4](07-data-requirements.md) の 3 年後）で主要 10 画面を計測し、95 パーセンタイルが 3 秒以内 | [目標] |
| `NFR-PERF-02` | 同時利用は 50 セッションを想定する | 50 セッション相当の負荷で `NFR-PERF-01` が保たれること | [目標] |
| `NFR-PERF-03` | 拡張性の水準を定めない。**想定規模を超えたときは構成の見直しから始める** | — | [対象外] |

## 4. セキュリティ

**この店が守ると決めた品質である。全項目 [必達] とする。**

| ID | 要件 | 測定 | 強制 |
| --- | --- | --- | --- |
| `NFR-SEC-01` | 全通信を暗号化する。平文でアクセスされたら HTTPS へ誘導し、本番では HSTS を付す | 平文のまま完結する応答が存在しないこと | [必達] |
| `NFR-SEC-02` | 未ログインで到達できる画面を、トップ・プライバシー・検索・書籍詳細・かご・欲しい物・エラーに限る | [06 §1](06-screens.md) の一覧との突き合わせ | [必達] |
| `NFR-SEC-03` | 管理者グループに属さない利用者は管理機能に到達できない | 管理者以外での管理画面・管理 API 到達が 0 であること | [必達] |
| `NFR-SEC-04` | 画面を経ない偽造された更新要求を拒否する | すべての更新系要求に検証が既定で適用されていること | [必達] |
| `NFR-SEC-05` | データベース資格情報をコード・リポジトリ・設定ファイルに置かない | 構成監査でリポジトリ内に資格情報が検出されないこと | [必達] |
| `NFR-SEC-06` | 不適正と判定された表紙画像を保存も配信もしない | [EXT-IMG-CHECK](08-external-interfaces.md) の禁止カテゴリの画像が配信されないこと | [必達] |
| `NFR-SEC-07` | 顧客向けの照会・操作を本人のデータに限る | 他人の識別子を指定した要求が 0 件の結果を返すこと（[RULE-ACCESS-01](05-business-rules.md)） | [必達] |
| `NFR-SEC-08` | 同じ 1 冊を二人に売らない。在庫の引き当ては注文の確定と同時に確定し、在庫を超える出庫を拒否する | 並行注文の試験で在庫が負にならず、二重販売が発生しないこと（[RULE-STOCK-03](05-business-rules.md)） | [必達] |

**[必達] の項目は、総合テストで検証した記録を成果物とする。**

## 5. 運用・保守性

| ID | 要件 | 測定 | 強制 |
| --- | --- | --- | --- |
| `NFR-OPS-01` | アプリケーションログを外部に送出し、30 日保持する | ログ検索で直近 30 日の操作が追えること | [必達] |
| `NFR-OPS-02` | 監視は、プロセスの死活とディスク使用率に限る。通知は運用者のメール宛て | 死活監視の発報試験が通ること | [必達] |
| `NFR-OPS-03` | 運用手順書（起動・停止・バックアップ・復旧・参照データ投入）を納品する | 成果物の存在 | [必達] |

## 6. 移行性

| ID | 要件 | 強制 |
| --- | --- | --- |
| `NFR-MIG-01` | 既存データの移行を行わない。初期在庫は稼働後に店が手入力する（[07 §6](07-data-requirements.md)） | [必達] |
| `NFR-MIG-02` | 参照データ（分類の選択肢）のみ、店が提供する一覧を投入する | [必達] |

## 7. システム環境

| ID | 要件 | 強制 |
| --- | --- | --- |
| `NFR-ENV-01` | 対応ブラウザは、稼働開始時点で提供元の保守対象にある Chrome / Edge / Safari / Firefox の最新版とする | [必達] |
| `NFR-ENV-02` | 画面は PC・タブレット・スマートフォンの幅に対応する | [必達] |
| `NFR-ENV-03` | 表示言語は英語のみ。文言の外部化・言語切替を行わない | [必達] |
| `NFR-A11Y-01` | アクセシビリティの到達水準を定めない | [対象外] |

## 8. 水準を定めない項目の一覧

**定めないことも要件である。** プロダクトが育ったときに改めて水準を定める。

| ID | 観点 | 定めない理由 |
| --- | --- | --- |
| `NFR-AVAIL-02` | 稼働率 | 単一構成で足りるという判断。冗長化は運用費の上限に劣後する |
| `NFR-PERF-03` | 拡張性 | 想定規模を超える見込みがない |
| `NFR-A11Y-01` | アクセシビリティ | 対応の範囲を決める材料が現時点でない |

受容するリスクは [12 課題とリスク](12-open-issues-and-risks.md) が持つ。
