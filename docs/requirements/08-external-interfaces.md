# 08 外部インタフェース

**システムの境界**と、その外にある依存先を定める。
どこまでが本システムの責任で、何を外部に委ねるかを確定させる。

API のパラメータ定義・リトライ・タイムアウト値は基本設計で定める。

## 1. 一覧

| ID | 連携先 | 委ねること | 失敗時の見え方 | フェーズ |
| --- | --- | --- | --- | --- |
| `EXT-AUTH` | Amazon Cognito | 本人確認、サインアップ、パスワード管理、氏名とメールの保持、管理者グループの所属判定 | ログインできない。未ログインで使える画面だけが使える | 1 |
| `EXT-IMG-STORE` | Amazon S3 ＋ CloudFront | 表紙画像の保管と配信 | 保管失敗は登録操作の業務エラー。配信失敗は画像だけ欠ける | 1 |
| `EXT-IMG-CHECK` | Amazon Rekognition | 表紙画像の適正判定 | 「不適正」は業務エラー。判定不能はシステムエラー | 1 |
| `EXT-CONFIG` | AWS Systems Manager Parameter Store ＋ Secrets Manager | 実行時構成とデータベース資格情報 | 起動時に読めなければアプリが起動しない | 1 |
| `EXT-LOGS` | Amazon CloudWatch Logs | アプリケーションログの保管 | 利用者からは観測されない | 1 |

## 2. 各連携先

### EXT-AUTH — 本人確認

| 項目 | 内容 |
| --- | --- |
| 委ねること | 本人確認、サインアップ、パスワード管理、氏名（姓・名）とメールアドレスの保持、管理者グループの所属判定 |
| 方式 | OpenID Connect（認可コードフロー ＋ PKCE）。ログイン画面は Cognito のホスト画面を用いる |
| 本システムが受け取るもの | 主体識別子、利用者名、姓、名、所属グループ |
| 契約 | **本システムはパスワードを預からない。** 主体識別子が顧客を特定する唯一の手段である |
| 失敗時 | 認証基盤に到達できない間はログインできない。未ログインで使える画面（トップ・検索・書籍詳細・かご・欲しい物・プライバシー）はそのまま使える |

**ログイン成立のたびに氏名を取り込み、顧客を登録・更新する。**
これが、顧客が自分の氏名を本システムの画面から編集できない理由である。

### EXT-IMG-STORE — 表紙画像の保管と配信

| 項目 | 内容 |
| --- | --- |
| 委ねること | 表紙画像の原本の保管（非公開）と、CDN 経由での配信 |
| 方式 | 保管は S3 API。配信は CloudFront への HTTPS GET のみ（バケットへの直接アクセスは拒否） |
| 契約 | 書籍が保持するのは配信 URL である |
| 制限 | png / jpg / jpeg、1 枚 2MB 以下 |
| 失敗時 | 保管に失敗した場合は書籍の登録・更新・棚入れを業務エラーとする。配信に失敗しても画面は表示され、画像だけが欠ける |
| 前提 | 配信ドメインは AWS が生成するものを用いる（独自ドメインを持たない） |

### EXT-IMG-CHECK — 表紙画像の適正判定

| 項目 | 内容 |
| --- | --- |
| 委ねること | 表紙画像が公開に適するかの判定 |
| 方式 | 画像 1 枚を渡し、適正／不適正の判定を受け取る |
| 判定基準 | 次の 10 カテゴリのいずれかに該当すれば不適正とする——露骨な性的表現、性的示唆、暴力、視覚的に不快、侮辱的ジェスチャー、薬物、たばこ、酒、賭博、ヘイトシンボル |
| 契約 | **画像なしは適正**として扱う。判定は書籍の登録・更新・棚入れでのみ行う |
| 失敗時 | 「不適正」の判定は業務エラーとしてその場で伝える。判定サービスに到達できない場合はシステムエラー |

**判定するのは保存する直前の状態である。**
表示に適した寸法へ調整した**後の**画像を判定する。調整で見え方が変わりうるためである。
危険と判定されたときは、**書籍も画像も保存しない。**

**判定基準は外部サービスの語彙をそのまま受け入れる。** 店独自の基準を持たない。

### EXT-CONFIG — 構成と秘匿情報

| 項目 | 内容 |
| --- | --- |
| 委ねること | 本番の実行時構成と、データベース資格情報の保管 |
| 方式 | 起動時に所定のパス以下のパラメータを読み込む。資格情報は秘密の保管庫から取得する |
| 失敗時 | 起動時に読めなければアプリが起動しない。実行中の失敗は起こらない（起動時にのみ読む） |
| 前提 | **資格情報をコード・リポジトリ・設定ファイルに置かない**（[NFR-SEC-05](09-non-functional-requirements.md)） |

### EXT-LOGS — ログの保管

| 項目 | 内容 |
| --- | --- |
| 委ねること | アプリケーションログの保管と保持（30 日） |
| 方式 | ログの送出のみ（片方向） |
| 失敗時 | 利用者からは観測されない。運用上はログが欠落する |

## 3. 存在しない連携先

**次の連携先は持たない。** 持たないことも要件である。

| 連携先 | 判断 |
| --- | --- |
| 決済代行 | [ADR-0001](decisions/ADR-0001-defer-online-payment.md)。注文の確定は支払を伴わない |
| メール送信基盤 | [ADR-0002](decisions/ADR-0002-defer-notifications.md)。進行は画面でのみ伝わる |
| 配送業者 | 追跡番号・配送業者・実出荷日を記録しない |
| 会計・在庫の既存システム | 店に既存システムがない（紙と表計算） |
| 相場・書誌情報の外部データベース | 値付けは店の裁量による（[RULE-TRADE-03](05-business-rules.md)） |

## 4. 開発環境での差し替え

開発・単体テストの間は、上記の連携先をすべてローカル実装に差し替えられるものとする。
**外部サービスへの接続なしに開発が進むこと**を要件とする。
差し替えの構成は [10 システム方式](10-system-architecture.md) が定める。
