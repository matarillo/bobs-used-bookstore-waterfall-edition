# 02 スコープ

**本章が契約上のスコープを定める。** ここに無いものは作らない。

## 1. 対象業務

| # | 業務 | 対象 | 備考 |
| --- | --- | --- | --- |
| 1 | 販売：書籍を探す・選ぶ | ● | 検索・詳細照会・かご・欲しい物リスト |
| 2 | 販売：注文する | ● | 配送先の指定と注文確定。**代金の授受は対象外** |
| 3 | 販売：注文を照会する・取り消す | ● | 顧客自身による照会と取消 |
| 4 | 販売：注文を履行する | ● | 店による受付・出荷・配達の記録 |
| 5 | 買取：申し込む | ● | 顧客が希望買取価格を申告する |
| 6 | 買取：審査する | ● | 店による承認・却下。**査定額の提示は対象外** |
| 7 | 買取：受領と支払を記録する | ● | 支払った事実の記録。**送金そのものは対象外** |
| 8 | 在庫：棚入れする | ● | 支払完了のオファーを書籍にする |
| 9 | 在庫：手入力で登録・更新する | ● | 買取以外の経路で入った本 |
| 10 | 在庫：分類の選択肢を保守する | ● | 出版社・書籍種別・ジャンル・コンディション |
| 11 | 経営：状況を把握する | ● | ダッシュボード |
| 12 | 会計・帳簿 | ✗ | 店の既存運用。古物商としての法定帳簿を含む |
| 13 | 配送手配 | ✗ | 店の既存運用 |
| 14 | 顧客への能動的な連絡 | ✗ | 電話・店頭。[ADR-0002](decisions/ADR-0002-defer-notifications.md) |
| 15 | 仕入先（法人）との取引 | ✗ | 買取は個人からのみ |

## 2. 対象利用者

| 利用者 | 対象 | 想定人数 |
| --- | --- | --- |
| 来店者（未ログインの訪問者） | ● | 制限なし |
| 顧客（ログインした訪問者） | ● | 稼働 1 年で 2,000 人程度 |
| 店舗スタッフ | ● | 店主を含め 3〜5 名 |

**スタッフの権限は 1 種類である。** 管理者グループに属していれば管理機能をすべて操作できる。
権限の細分化は対象外とする（[ISSUE-06](12-open-issues-and-risks.md)）。

## 3. 対象チャネル・環境

| 事項 | 対象 |
| --- | --- |
| チャネル | PC・タブレット・スマートフォンの Web ブラウザ |
| 言語 | 英語のみ |
| 通貨 | 単一通貨 |
| 配送先 | 米国内のみ（州は 50 州＋首都特別区の固定選択） |
| ネイティブアプリ | ✗ |
| 店頭 POS・既存業務システムとの連携 | ✗（現行の店頭業務は紙と表計算で回っている） |
| 既存データの移行 | ✗（在庫は稼働後に手入力で登録する — [ISSUE-01](12-open-issues-and-risks.md)） |

## 4. フェーズ分割

一括で作らず、**店の業務が立ち上がる順**に 2 フェーズへ分ける。
フェーズ 1 のリリースをもって検収する。

| フェーズ | 範囲 | 届ける相手 | 位置づけ |
| --- | --- | --- | --- |
| **フェーズ 1** | 販売の全体（探す・買う・履行する）＋ 在庫の手入力登録 ＋ 参照データ保守 ＋ ダッシュボード | 市場・店舗スタッフ | **本契約の対象** |
| **フェーズ 2** | 買取の全体（申込・審査・受領・支払・棚入れ） | 顧客・店舗スタッフ | **本契約の対象** |

**フェーズ 1 が先である理由**: 売る本がない店に買取客は来ない。
在庫を手入力で載せられる状態を先に作り、販売の循環を立ち上げてから買取を開く。

**フェーズ 2 の機能もフェーズ 1 と同時に要件を確定させる。**
買取は在庫（書籍）と分類（参照データ）を共有しており、
データ構造を後から足すと手戻りになるためである。

各機能がどのフェーズに属するかは [04 機能要件](04-functional-requirements.md) の「フェーズ」列が定める。

## 5. 優先度

各機能に優先度を付す。**納期が逼迫したときは、この順で調整する。**

| 優先度 | 意味 | 逼迫時の扱い |
| --- | --- | --- |
| **必須** | 欠けると業務が回らない | 動かさない |
| **推奨** | 欠けても業務は回るが、運用の手間が増える | フェーズ 2 へ送る協議の対象 |
| **任意** | あれば便利 | 最初に落とす |

**譲る順は スコープ → 納期 → コスト → 品質 である。**
品質のうち次の 4 点は、スコープや納期を犠牲にしても守る（[09 非機能要件](09-non-functional-requirements.md)）。

- 金額が常に正しいこと（成立した取引の金額が後から変わらない）
- 同じ 1 冊を二人に売らないこと
- 本人のものしか見せない・触らせないこと
- 通信の暗号化と、画面を経ない更新要求の拒否

## 6. スコープに含まれる成果物

| 工程 | 成果物 |
| --- | --- |
| 基本設計 | 画面設計書（全画面）、API 一覧・定義、テーブル定義書、外部 I/F 設計書、バッチ設計書（該当なし） |
| 詳細設計・実装 | ソースコード、単体テスト仕様書・結果 |
| 試験 | 結合テスト仕様書・結果、総合テスト仕様書・結果 |
| 移行・運用 | 環境構築手順書、運用手順書、参照データ初期投入手順 |
| 教育 | スタッフ向け操作説明書（管理機能）、操作説明会 1 回 |

**含まれないもの**: 顧客向けマニュアル、運用代行、稼働後の保守（別契約）。
