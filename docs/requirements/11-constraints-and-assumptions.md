# 11 前提と制約

**見積の土台になる前提**を置く。ここが崩れると金額と納期が動く
（[規模・体制・スケジュール §5](../estimate/scope-and-schedule.md)）。

## 1. 利用者と規模

| 事項 | 前提 |
| --- | --- |
| 利用者のリテラシ | 一般消費者。訓練・マニュアルを前提にしない |
| スタッフ | 店主を含め 3〜5 名。管理画面は日々の業務の中で覚えられる範囲に収める |
| 同時アクセス | ピークで 50 セッション（[NFR-PERF-02](09-non-functional-requirements.md)） |
| データ量 | [07 §4](07-data-requirements.md) の 3 年後の見当を上限とする |

## 2. 業務の前提

| 事項 | 前提 |
| --- | --- |
| 代金の授受 | **システムの外**で行う。注文＝支払ではない（[ADR-0001](decisions/ADR-0001-defer-online-payment.md)） |
| 配送 | **システムの外**で行う。追跡番号・送り状を扱わない |
| 買取 | **1 申込 1 冊**。現物は店に届いて検分される |
| 配送先 | **米国内のみ**。州は 50 州＋首都特別区の固定選択、国は固定表示 |
| 通貨と税 | 単一通貨。**単一税率 10% の固定**。地域差・軽減税率を扱わない |
| 古物商の許認可・法定帳簿 | **店側の運用**で満たす。システムの責務にしない |
| 店頭業務 | 現行のまま。システムと連携しない。**オンライン在庫と店頭在庫は別に管理される** |

## 3. 技術・運用の前提

| 事項 | 前提 |
| --- | --- |
| 認証 | 外部認証基盤に委ねる。**パスワードを預からない**（[EXT-AUTH](08-external-interfaces.md)） |
| 個人情報 | 預かるのは氏名・メールアドレス・配送先住所のみ。メールは外部認証基盤が持つ |
| 実行基盤 | AWS。既存のアカウントと請求を用いる |
| 運用費 | **月額の上限を設ける。** 冗長化・NAT・複数環境の常時起動は上限に劣後する |
| ドメイン名・証明書 | 店が用意する。取得と更新は店の責任 |
| 独自の画像配信ドメイン | 持たない。AWS が生成するドメインを用いる |
| 運用 | 稼働後の運用は店が行う。ベンダの運用代行は本契約に含まない |

## 4. プロジェクトの前提

| 事項 | 前提 |
| --- | --- |
| 顧客側の体制 | 店主が意思決定者を兼ねる。**業務確認の回答は 3 営業日以内に得られる** |
| レビュー | 各工程の完了レビューを 1 回行う。指摘の反映は 5 営業日以内 |
| 参照データの提供 | 分類の選択肢一覧を、基本設計完了までに店が提供する |
| 初期在庫の登録 | **稼働後に店が行う。** ベンダは作業しない |
| 検収 | フェーズ 1 とフェーズ 2 のそれぞれで行う |
| 開発場所 | ベンダ拠点。顧客先常駐を前提にしない |

## 5. 前提が崩れたときの扱い

前提はコスト・規模・法規の変化で動く。
変えるときは、**スコープ・金額・納期への影響を評価してから**変える。

影響が大きい前提を挙げる。

| 前提 | 崩れた場合の影響 |
| --- | --- |
| 代金の授受がシステムの外 | 決済機能が丸ごと追加になる。**再見積を要する** |
| 米国内のみの配送 | 住所の構造・税の扱いが変わる。**再見積を要する** |
| 単一税率 10% | 税の計算と表示が変わる。**再見積を要する** |
| 既存データを移行しない | 移行設計・移行ツール・移行リハーサルが追加になる。**再見積を要する** |
| 店頭業務と連携しない | 連携インタフェースが追加になる。**再見積を要する** |
| スタッフの権限が 1 種類 | 権限管理機能が追加になる。**再見積を要する** |
| 回答が 3 営業日以内 | 工程が遅延する。**納期の見直しを要する** |
